# 外部评审分析与演进方案

本文件记录两次外部 AI 评审（DeepSeek、ChatGPT）的阅读结果、可信度评估，以及由此得出的演进取舍。
凡未经本仓库验证的说法都标明来源，不冒充事实。

## 二、ChatGPT 的核心论点（归纳）

1. **定位**：核心价值不是"架构可视化"，而是"帮助开发者理解复杂代码库，并让理解结果有证据可追溯"。产品名 `Architecture Visualization` 会让用户误以为"把代码变成架构图"，而画图只是最后一种呈现。
2. **核心壁垒**：`node/edge → evidenceIds(file:line) + status + confidence`，加上采集不到就报 `unsupported_input` 而不是当作不存在。它认为这是整个项目真正的护城河。
3. **五大价值**：陌生代码库理解、影响分析、识别"你不知道自己不知道什么"、模型健康检查、可交付物导出。
4. **最大问题是产品问题而非技术问题**："用户到底什么时候会主动打开这个插件？"用户不会说"我要查看 Architecture Model"，而会说"我改这里会影响什么"。
5. **入口设计错了**：现在要求"准备模型 → 加载模型 → 查询模型"，应该是"打开插件 → 分析项目"。
6. **它给的 5 个改动排序**：① 一键 Analyze Project（把 model.json 隐藏掉）② 真正的 Interactive Graph ③ Evidence → Source（点击关系看 `file:line` 并跳转）④ Git Diff → Impact ⑤ Architecture Drift。
7. **技术建议是"少做一些"**：不要再增加 `architecture-xxx` 技能；前台只保留 Understand / Impact / Risk / Drift 四个概念。
8. **明确肯定**：权限克制（只 `fs.read` + UI + Agent）、盲区可见、不把未实现包装成已实现。**明确不建议重做**："保留现在的核心模型和证据体系，重新做用户工作流"。

## 四、演进方案（按"成本 × 价值 × 是否违背现有原则"排序）

### P0 — 零新权限、直接放大核心差异化（本轮已做）

1. **证据可打开**：证据条目加"打开"动作，走 `pluginBridge.invoke('fs.openDefault', { path })`。
   验收：点击后宿主编辑器打开对应文件；路径非法或不可读时给出稳定错误码，不静默失败。
2. **导出可复制**：导出预览加"复制"动作，走白名单里的 `clipboard.writeText`。
   验收：复制后面板明示成功；剪贴板不可用时报告受限，不假装成功。

### P1 — 让名字名实相符

3. **面板内交互关系图**：用 SVG 渲染当前模型，支持点击节点联动右侧详情、高亮直接上下游、按 `status` 着色、按类型/状态筛选、缩放与平移。纯本地，零新依赖。
   验收：节点集合与模型一致；点击节点后详情与证据联动；截图可复核；`renderer` 测试固定交互。
4. **首页重组**：把"采集并生成模型"提为主操作（首要按钮、首页可见），"读取模型"降为高级入口并明示"已有模型文件时用"。

### P2 — 让影响分析进入日常（需要设计决策，不动 Git 推断）

5. **显式变更集影响**：接受一组工作区相对文件路径（用户输入或 agent 提供），映射到模型节点后跑影响分析，输出"变化的节点 / 受影响的节点 / 建议复核的测试与接口"。
   明确不做：读 Git、推断分支、推断未提交改动——那会让 `evidenceFreshness` 从"未知"变成谎言。
6. **架构漂移**：支持 `state: target` 与 `state: current` 的对照，输出"声明存在但代码没有 / 代码存在但未声明"两类差异，各带证据。

### 明确不做（以及为什么）

- **申请 `fs.write` 自动保存模型**：宿主 `writeText` 是直接覆盖，会毁掉人工补过的模型。内容寻址快照方案已记录在 `architecture/decisions/no-safe-publish-primitive.md`，等授权且 scope 限定 `architecture/snapshots/**` 后再做。
- **新增架构技能**：同意"少做一些"。前台概念压到 Understand / Impact / Risk 三个，其余归 `docs/`。
- **采集器改写成 AST 解析器**：工作量大，且会改变全部 `evidence.line` 的语义（现在是行号命中，AST 后会变成节点位置）。当前面向行启发式的局限已如实写进 CHANGELOG 与夹具清单，不伪装。
- **读取 Git 状态**：见 P2 说明。

## 五、验收标准

- P0：`node --test tests/*.test.js` 全绿；浏览器预览实测点击证据能打开文件、复制能写入剪贴板。
- P1：关系图的节点/边集合与模型逐一对应（测试固定）；首页重组后"零前置条件下三步内得到可查询模型"仍成立。
- P2：变更集影响不引入任何 Git 读取；漂移输出的每条差异都带 `evidenceIds`。
- 全阶段：不新增权限；受控失败仍以稳定错误码呈现，不静默降级。
